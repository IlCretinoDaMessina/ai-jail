<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config.env → bat execution | User-edited KEY=VALUE file is parsed and executed as variables — untrusted characters (`!`, `&`, `=`, quotes) cross here |
| bat → logs\ | Child process stdout is captured to files under the repo |
| _common.bat → Linux filesystem (later phases) | The LF writer will emit files consumed by bash — byte-level corruption crosses here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Tampering | config.env parsing in `_common.bat :load` | mitigate | Parse under `DisableDelayedExpansion` so `!` in values survives (t13 vs t16); quoted `set "K=V"` so `&` never becomes a command separator; `eol=# tokens=1,* delims==` so `=` in values survives. Asserted by `tests\verify-config-load.cmd`. |
| T-1-02 | Tampering | exit-code classification in `_common.bat :run_phase` / `:classify_rc` | mitigate | Capture-first rule (`set "RC=!ERRORLEVEL!"`) defeats stale `%ERRORLEVEL%` in parsed blocks (t8); exact `EQU` matching with 3010 checked before `EQU 1` because `if errorlevel 1` is ≥-semantics (t1) and would mis-route reboot as fatal; rc outside {0,1,3010} → classified 1 (fail-closed, unknown codes never read as success). Asserted by `tests\verify-exit-contract.cmd`. |
| T-1-03 | Tampering | LF payload emission `_common.bat :write_lf` | mitigate | PowerShell writer with `-replace "`r`n","`n"` and UTF8 no-BOM encoding; byte-asserted by `tests\bytecheck.ps1` (no 0x0D, no EF BB BF) so CR/BOM poisoning of future Linux-side files cannot pass silently. |
| T-1-SC | Supply chain | npm/pip/cargo package installs | accept | Phase 1 installs no packages (pure cmd + in-box PowerShell 5.1). First package surface is Phase 3 `cargo install --locked ai-jail`, gated there. |
</threat_model>
